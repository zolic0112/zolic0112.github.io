# Build checklist — 三種視覺系統共用

Work through this before presenting the file. These are the things that separate a page that photographs well from one that survives being opened on a phone, shared on LINE, and read with a keyboard.

## Structure

- Semantic elements: `<header> <nav> <main> <section> <article> <footer>`. One `<h1>`. Headings descend without skipping levels.
- Every section has an `id` matching its nav link.
- Inline `<style>` and `<script>`. Google Fonts are optional; when used, add `preconnect`, `display=swap`, and a system-font fallback. No CDN frameworks.
- Inline SVG for icons and decorative graphics. No icon fonts, no image requests for shapes.

## Responsive

- Check mentally at 375px, 768px, 1440px.
- Multi-column grids collapse to one below 768px; sticky sidebars become a static header block below 900px.
- Type uses `clamp()` rather than per-breakpoint overrides.
- Tap targets ≥ 44px. Any horizontal scroll is a bug — check long unbroken strings (emails, URLs) with `overflow-wrap: anywhere`.
- Use `100dvh`, not `100vh`, for full-height sections. Mobile browser chrome makes `vh` wrong by exactly the height of the address bar.
- Components that appear in containers of different widths use `@container`, not media queries.

## Accessibility

- Contrast: body text ≥ 4.5:1 against its **actual** background, large display text ≥ 3:1. Muted body colors are where light styles fail — verify rather than assume.
- Visible focus rings on every link, button, and input. Never `outline: none` without a replacement.
- Tab order matches visual order. CSS Grid placement can silently break this — if a cell was moved with `grid-column`/`grid-row`, fix the source order instead.
- `alt` on informative images, `alt=""` on decorative ones. Grain overlays, washes, blobs, grid lines, and marquees are decorative → `aria-hidden="true"`.
- Skip-to-content link as the first focusable element.
- One `@media (prefers-reduced-motion: reduce)` block that neutralizes every animation to its end state — off, not shortened. Any looping animation (marquee, drift, pulse) must fully stop.
- Interactive icon-only controls need an `aria-label`.

## SEO / AEO

- `<title>` in the form `Name — what it is` (under ~60 chars).
- `<meta name="description">`, 140–160 chars, written not templated.
- Open Graph: `og:title`, `og:description`, `og:type`, `og:url`, `og:image`. Omit `og:image` entirely rather than pointing at a file that doesn't exist — a broken preview is worse than a text-only one.
- `twitter:card="summary_large_image"` when there is an image.
- `<link rel="canonical">` with a commented placeholder for their eventual domain.
- JSON-LD for the real entity: `Organization`, `LocalBusiness`, `Person`, `Product`, `Event`, or `SoftwareApplication`. Add `FAQPage` if there's an FAQ.
- Favicon as an inline SVG data URI in the accent color — avoids a 404 on every load.
- Headings phrased as answers to real questions, since answer engines quote them.

## Performance

- ≤ 2 font families, ≤ 4 weights total, `display=swap`.
- Animate only `transform` and `opacity`. Exception: one `font-variation-settings` animation in the Editorial style, on a single element.
- Don't set `will-change` preemptively.
- `loading="lazy"` plus explicit `width`/`height` on below-fold images — the dimensions prevent layout shift.
- Disconnect IntersectionObservers after firing.
- Prefer `animation-timeline: view()` inside `@supports`, with the observer as the fallback path.

## Content

- No lorem ipsum, no "Feature One", no placeholder project names.
- No invented testimonials, client logos, customer counts, awards, or statistics on a real commercial site. Bracket them as placeholders instead.
- No stock phrases: "passionate", "results-driven", "seamless experience", "革命性的", "一站式解決方案", "打造無縫體驗".
- Every CTA uses the same words wherever it appears. The button that says 預約諮詢 leads to a section headed 預約諮詢.
- Contact actions are real: `mailto:`, `tel:`, actual profile URLs. A form with no backend is worse than an email address — if they want a form, either wire it to Formspree with a commented setup line or explain why mailto is better.
- External links get `rel="noopener noreferrer"`.
- Footer year generated by JS, not hardcoded.

## Final pass

Read the rendered page as the intended visitor with 20 seconds and a thumb. Can they tell what this is, who it's for, and what to do next — before scrolling? If not, fix the hero copy. That's almost always the problem, and it's almost never the design.
